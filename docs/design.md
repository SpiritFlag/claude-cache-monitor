# 설계 근거

화면에 뜨는 수치를 어떻게 뽑는지, 그것을 어떻게 읽어야 하는지를 적는다. 쓰는 법은 [README](../README.md)에, 운영은 [guide.md](guide.md)에 있다.

## 보정값

시스템 바닥 · 압축 후 요약 크기 · 다시 읽기 양은 **지켜보는 폴더에서 실측한 중앙값**을 쓴다. 표본이 없으면 기본값(45k · 20k · 80k)을 쓰고 팝업에 "기본값, 샘플 없음"으로 표시한다. 콜드스타트 세션 하나와 압축 한 번이 관측되면 그때부터 실측값으로 바뀐다.

폴더마다 시스템 바닥이 다른 이유는 MCP 구성과 프로젝트 층이 컨텍스트 앞머리에 함께 실리기 때문이다. 그래서 보정은 전역이 아니라 폴더 단위로 잡는다.

## 숫자 읽는 법

- 달러는 API 정가 환산이다. 구독제로 쓰고 있다면 금액 자체보다 사용량 한도를 얼마나 태우고 있는지의 감각으로 본다.
- 캐시 깨짐 비용은 `다시 쓴 토큰 × (쓰기 단가 − 읽기 단가)`다. 1시간 캐시 기준으로 쓰기는 2배, 읽기는 0.1배다(Fable 5.1은 0.025배).
- 컨텍스트 구성 비율은 문자 수 비율을 실제 컨텍스트 크기에 맞춰 늘린 추정치다. 합계는 정확하고 비율에 몇 %의 오차가 있다.
- 압축은 캐시가 살아 있을 때 해야 이득이다. 만료된 뒤의 압축은 그 호출이 전체를 다시 쓴다.
- 만료 후 "이어가기"와 "새 세션"의 손익분기는 `컨텍스트 = 시스템 바닥 + 다시 읽기`다. 그 아래면 이어가고 위면 새 세션이 싸다.

## 판정

캐시가 깨진 원인은 브레이크 레코드의 진단 필드로 분류한다. 분류 규칙과 각 원인의 정의는 코드(`server.js`)와 판정 테스트(`test/*.test.js`)가 정본이다. 새 원인을 추가할 때는 합성 픽스처를 먼저 만들고 그것을 통과시키는 방식으로 넣는다.
