# v1.3.0 enhance-subagent — scope

| 사이클 | 버전 | 상태 | 작성 | 갱신 |

| enhance-subagent | v1.3.0 | 확정 | 2026-09-10 | 2026-09-10 |

## 1. 목적

계기판이 서브에이전트가 낀 세션에서 거짓말을 한다. 비용은 서브 것까지 전부 세면서 활성 시간은 메인 것만 세고, 서브가 보내온 완료 알림을 사람이 친 프롬프트로 세고, 서브의 캐시가 만료돼 다시 쓰인 것을 원인 미상으로 적는다. 세 가지가 한 세션에서 동시에 일어나면 시간당 비용이 네 배로 부풀고 프롬프트 수가 다섯 배로 부풀며 손실의 출처를 알 수 없게 된다.

뿌리는 하나다. 서브에이전트가 집계에서 **일급 대상이 아니다**. 지금 코드는 서브를 "메인이 아닌 것"으로만 알고, 쓰임에 따라 어떤 값에서는 빼고 어떤 값에서는 넣는다. 그 기준이 자리마다 달라 값들이 서로 어긋난다.

이 사이클은 서브에이전트를 세션 아래의 집계 단위로 세우고, 화면에서 선택할 수 있는 대상으로 만든다. 그러면 분자와 분모가 같은 대상을 가리키게 되어 시간당 비용이 제자리를 찾고, 서브가 얼마를 태웠는지가 이름과 함께 보인다.

지금인 이유는 표본이 생겼기 때문이다. 사용자가 서브에이전트 여섯을 동시에 돌린 세션 하나가 세 증상을 한꺼번에 담고 있고, 그 안에서 이슈 #5가 기다리던 관측 조건도 함께 충족됐다.

## 2. 항목

### 2.1 서브에이전트를 집계 단위로 세운다

- **무엇을**: 지금은 서브 호출의 비용이 `s.cost`에 그대로 더해지는데(server.js:310 — `isSub` 조건 없음) 활성 시간은 `trackActive`가 서브를 첫 줄에서 되돌려보내(server.js:205) 0으로 남는다. 분자만 세고 분모는 안 세는 구조다. 앞으로는 세션이 **메인 값과 서브 값을 따로** 들고, 서브는 파일(=에이전트)마다 비용·활성 시간·컨텍스트·호출 수·캐시 깨짐을 각각 갖는다. 메인 세션의 값에서는 서브 몫이 빠진다. 서브마다 같은 폴더의 `agent-*.meta.json`을 읽어 `description`(없으면 `agentType`)을 이름으로 붙인다.
- **어떻게**: 서버의 집계 층. `files` 맵이 이미 파일 단위이고 `f.isSub`가 서브를 가리키므로, 세션 하나에 서브 집계 슬롯을 파일 단위로 붙인다. `scan`이 지금 `.jsonl`만 읽으므로 `.meta.json`을 함께 읽는 자리를 하나 연다. `snapshot`이 세션마다 서브 목록을 함께 내보낸다.
- **왜**: 값을 하나로 두고 "어떤 화면에서는 서브를 넣고 어떤 화면에서는 뺀다"로 가면 지금과 같은 어긋남이 다시 생긴다. 대상을 갈라 두면 어느 화면이든 자기가 가리키는 대상의 값을 그대로 쓰면 된다. 활성 시간을 메인+서브 합산 한 값으로 두는 안을 먼저 검토했으나, 그렇게 하면 그래프의 x축(활성 시간 누적)이 서브 몫만큼 늘어나는데 그래프에는 서브 점이 없어 빈 구간이 생긴다. 대상을 가르면 그래프 축은 손댈 필요가 없다.
- **끝났다는 기준**: 표본 세션에서 메인은 `$13.22 / 24분`, 서브 여섯의 소계는 `$40.40 / 1.5시간` 부근으로 갈라져 나오고, 두 값의 합이 지금의 세션 합계 `$53.62`와 같다. 서브 여섯이 각각 이름을 갖는다.

### 2.2 세션 목록에 서브에이전트 행을 붙이고 고를 수 있게 한다

- **무엇을**: 지금 세션 목록은 세션마다 한 줄이고 서브가 몇이 돌았는지 알 길이 없다. 서브를 가진 세션 아래에 **들여쓴 줄 하나**가 붙어 서브 전체의 소계(비용·활성 시간·개수)를 보여주고, 그 줄을 고르면 오른쪽이 서브 기준 화면으로 바뀐다. 같은 작업에서 세션 줄의 시간 칸을 마지막 활동 경과(`ago(now - s.lastTs)`)에서 활성 시간으로 바꾼다(#26).
- **어떻게**: index.html의 세션 목록 렌더와 선택 상태. 지금 선택 상태는 세션 id 하나(`selected`)인데, 서브 줄이 선택 대상이 되므로 "무엇이 골라졌나"를 세션과 서브 둘 다 가리킬 수 있게 넓힌다.
- **왜**: 서브가 메인보다 세 배 비싼 세션이 목록에서는 한 줄로만 보인다. 소계를 목록에 두면 어느 세션에서 서브가 돈을 태웠는지 고르기 전에 알 수 있다. #26을 따로 세우지 않고 여기에 넣은 것은, 세션 줄을 어차피 다시 그리는데 시간 칸만 별도 항목으로 두는 것이 부자연스럽기 때문이다.
- **끝났다는 기준**: 표본 세션 아래에 서브 줄이 하나 붙고 소계가 2.1의 값과 같다. 서브가 없는 세션에는 줄이 붙지 않는다. 세션 줄의 시간 칸이 활성 시간으로 보인다.

### 2.3 서브를 고르면 TTL 카드 자리에 서브 목록이 나온다

- **무엇을**: 지금 오른쪽 위에는 Cache TTL 카드가 있는데(index.html:248) 서브를 보는 동안 세션의 TTL은 가리키는 대상이 없다. 서브 줄을 고르면 그 자리에 **서브 목록**이 들어서고, 목록에서 하나를 고르면 CONTEXT 카드·COST 카드·그래프가 그 서브의 값으로 바뀐다. 메인 세션을 고른 동안에는 지금의 TTL 카드가 그대로 있다.
- **어떻게**: index.html의 오른쪽 카드 배치. 카드를 지우는 것이 아니라 고른 대상에 따라 그 자리에 들어설 것을 가른다. 서브의 그래프·캐시 깨짐 표시는 세션의 것과 같은 그리기 코드를 쓴다.
- **왜**: 서브마다 컨텍스트 20만 토큰대에 비용이 5~9달러다. 소계만으로는 어느 서브가 비쌌는지 알 수 없고, 이름이 붙으므로 고르면 바로 안다. 그래프에 메인과 서브를 겹쳐 그리는 안은 버렸다 — 그래프는 메인 컨텍스트가 시간에 따라 어떻게 자랐는지를 보는 화면이고, 거기에 다른 대상의 선을 얹으면 그 뜻이 흐려진다. 대상을 골라 화면 전체가 그 대상을 가리키게 하는 편이 일관된다.
- **끝났다는 기준**: 표본 세션에서 서브 여섯이 이름과 함께 목록에 뜨고, 하나를 고르면 그 서브의 컨텍스트·비용·활성 시간이 2.1의 값과 같게 보이며 그래프가 그 서브의 것으로 그려진다.

### 2.4 서브에이전트 완료 알림을 사람이 친 프롬프트에서 뺀다

- **무엇을**: 지금 `human` 판정(server.js:280)이 "메타가 아니고 블록이 전부 text 또는 image면 사람"이다. 서브가 일을 마치면 그 결과가 `<task-notification>`으로 시작하는 text 블록으로 들어오는데 이 조건을 그대로 통과한다. IDE가 파일을 여는 `<ide_opened_file>`도 마찬가지다. 표본 세션에서 프롬프트로 세어진 15건 중 **사람이 친 것은 3건**이고 11건이 완료 알림, 1건이 IDE 이벤트다. 앞으로는 이 둘이 프롬프트에서 빠지고, 컨텍스트 구성의 "내 프롬프트" 층(server.js:285 `f.comp.user`)에서도 빠진다.
- **어떻게**: `human` 판정에 제외 목록을 둔다. 본문 첫머리의 태그 이름으로 가른다.
- **왜**: 프롬프트 수는 그 자체로도 보이고 시간당 프롬프트 같은 파생 표시의 분모이기도 해서, 다섯 배로 부풀면 딸린 표시가 모두 틀어진다. 컨텍스트 구성에서도 알림 11건이 7~8천 자씩 "내 프롬프트" 층에 들어가 7만 자 가까이 부풀어 있다. 태그 이름으로 가르는 것이 약한 신호라는 점은 알고 간다 — 이 줄들에는 `isMeta` 같은 플래그가 붙지 않아 다른 단서가 없고, 클로드 코드가 태그 이름을 바꾸면 조용히 다시 샌다. 사용자가 이 한계를 알고 태그로 가기로 정했다. 4절에 위험으로 적는다.
- **끝났다는 기준**: 표본 세션의 프롬프트 수가 15에서 3으로 줄고, 컨텍스트 구성의 "내 프롬프트" 층이 그만큼 줄어든다.

### 2.5 캐시 만료 판정을 세션 단위에서 호출 단위로 옮긴다 (#5)

- **무엇을**: 지금 만료 판정(server.js:333)이 세션 하나가 들고 있는 대표값 `s.ttlMin`을 본다. 그런데 그 값은 서브 호출로도 덮어써지고(server.js:319 — `isSub` 조건 없음), 판정은 **그 시점까지 읽힌 값**에 의존한다. 그래서 같은 데이터를 읽는 순서만 바꿔도 원인이 뒤집힌다. 표본 세션에서 실측했다 — 서브 파일을 먼저 읽으면 `ttl_expiry` 6건, 메인 파일을 먼저 읽으면 `unexplained` 6건이다. 실사용에서는 메인이 먼저 읽히므로 화면에는 미규명으로 뜬다. 앞으로는 **직전 호출이 실제로 어느 TTL로 캐시를 썼는지**로 판정한다. 그리고 `s.ttlMin`은 화면용 값으로 남기되 메인 호출로만 갱신한다.
- **어떻게**: `f.prev`에 그 호출의 `cw1h`·`cw5m`을 담고, 만료 기준을 거기서 뽑는다. `f.prev`가 파일 단위이므로 메인은 메인의 TTL로, 서브는 서브의 TTL로 각자 판정된다. `s.ttlMin`은 TTL 카드·잔여 시간·live/dead·캐릭터 상태(server.js:402, index.html 4곳)에서 계속 쓰이므로 없애지 않는다.
- **왜**: 이슈 #5는 미규명 4건 중 하나(`5f111656`, gap 14.8분)에 대해 "직전 호출이 실제로 어느 TTL로 캐시를 썼는지를 호출별로 남겨야 갈린다"고 적고, 그런 필드가 생길 때까지 착수를 미뤄 두었다. 그 필드는 이미 로그에 있다 — 읽고 있지 않았을 뿐이다. 표본 세션의 6건이 정확히 같은 모양이다: gap 25.8~28.4분으로 5분은 넘고 60분은 안 넘는 구간이며, 서브의 캐시 쓰기는 전부 5분 자리에 들어가 있다(`cw1h=0`, `cw5m` 12만~19만). 새 규칙을 지어내는 것이 아니라 이미 기록된 사실을 읽는 것이므로, #5가 함께 금지한 "원인을 모르는 채 분류 규칙을 더 넣는 일"에 해당하지 않는다.
- **끝났다는 기준**: 표본 세션을 **어떤 순서로 읽어도** `ttl_expiry` 6건으로 같게 나온다. #5가 지목한 `5f111656` 건이 미규명에서 벗어난다. TTL 카드는 메인 기준 그대로다.

## 3. 제외

- **캐시 만료를 미리 경고하는 화면.** 표본에서 실측한 결과 사용자가 손을 쓸 수 있는 창이 없었다. 서브 여섯의 캐시는 1차 결과가 도착하고 5분 안에 차례로 만료됐고(07:06:47~07:10:37), 사용자가 검토를 시작한 시각(07:11:22)에는 여섯 모두 이미 만료된 뒤였다. 보고서 여섯을 5분 안에 읽고 다음 지시를 내리는 것이 불가능하므로, 미리 알려도 살릴 수 없다. 이 사이클은 손실을 막는 대신 손실의 출처를 정확히 보이는 데까지만 한다.
- **서브 캐시 깨짐으로 캐릭터를 깨우는 것.** 위와 같은 이유로 사용자가 대응할 수 없는 일이고, 반응시키면 소음이 된다. 다만 서브가 하나라도 돌고 있으면 캐릭터가 작업 중으로 보이게 하는 것은 2.1~2.3에 딸린 표시로 다룬다 — 지금 `charState`(server.js:402)는 `s.subActive`를 보지 않아, 세션 목록의 불은 켜지는데 캐릭터만 멍하니 있다.
- **사용자가 검토한 시간을 재는 것.** 표본에서 사용자가 검토 구간을 직접 표시하려고 프롬프트 하나를 마커로 찍어 둔 것이 관측됐다. 도구가 그 시간을 어디에도 보여주지 않는다는 뜻이지만, 이번 실측에서 그 시간은 캐시 손실의 원인이 아니었고 이 사이클의 줄기와도 닿지 않는다. 닫을 때 이슈로 남긴다.
- **그래프에 메인과 서브를 겹쳐 그리는 것.** 2.3에서 버린 길이다.
- **서브에이전트 안의 서브에이전트.** `meta.json`에 `spawnDepth`가 있어 중첩이 가능해 보이지만 표본에는 전부 1이다. 표본 없이 계층을 설계하지 않는다.

## 4. 불확실 · 선행

- **태그 이름에 기댄 판정(2.4).** `<task-notification>`·`<ide_opened_file>`은 클로드 코드가 정하는 문자열이고 바뀌면 조용히 다시 샌다. 사용자가 이 한계를 알고 택했다. 구현할 때 제외 목록을 한자리에 모아 두어, 새 태그가 나타나면 그 한 곳만 고치면 되게 한다.
- **활성 시간 축의 단조성(2.1).** `activeAt`(server.js:189)은 활성 누적이 뒤로 가지 않도록 `Math.max`로 눌러 두었다. 서브 집계를 갈라 세우면 세션의 활성 누적이 지금과 같은 값으로 남으므로 영향이 없어야 하지만, 서브 자신의 그래프 축(2.3)은 새로 만드는 것이라 같은 성질이 필요한지 계획 단계에서 확인한다.
- **표본이 하나다.** 아래 수치는 모두 세션 `1904d418`(2026-09-10, 서브 6) 하나에서 나왔다. 서브를 하나만 쓴 세션, 서브를 중간에 멈춘 세션에서 같은 코드가 어떻게 도는지는 보지 않았다. 계획 단계에서 `data/` 안의 다른 서브 보유 세션을 훑어 예외 모양을 찾는다.
- **`.meta.json`이 항상 있는지 모른다(2.1).** 표본에서는 서브 여섯 모두 짝이 있었다. 없을 때의 이름을 정해 둔다.
