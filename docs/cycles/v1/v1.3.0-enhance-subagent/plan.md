> **scope 수치 정정 하나.** scope §2.4는 표본 세션의 프롬프트 15건을 "사람 3 · 완료 알림 11 · IDE 이벤트 1"로 갈랐고 끝났다는 기준을 "15에서 3으로"로 적었다. 15건을 한 줄씩 다시 열어 보니 IDE 이벤트로 센 그 1건은 **`<ide_opened_file>` 블록 뒤에 사람이 친 글이 한 블록 더 붙어 있는 레코드**였다. `data/` 전체에서 `<ide_opened_file>` · `<ide_selection>`으로 시작하는 레코드 9건을 모두 열어 봐도 예외 없이 같은 모양이다 — IDE가 파일 열림 사실을 앞에 끼워 넣고 그 뒤에 사용자의 말이 온다. 그러니 레코드째로 버리면 진짜 프롬프트 9건이 같이 사라진다. **블록 단위로 걸러야 하고, 그러면 표본은 15 → 4다.** 이 문서와 `design.md`는 4를 쓴다(§1.4 · D-3).

## 1. 바뀌는 것

### 1.1 서브에이전트를 집계 단위로 세운다

**지금 구조.** 서버는 로그 파일 하나마다 "프레임" `f`를 두고(`files` 맵, `server.js:34`), 파일이 `subagents/` 폴더 아래면 `f.isSub = true`로 표시한다(`server.js:383`). 세션 상태 `s`는 `sessionId`로 하나다. 서브 파일의 모든 줄은 메인과 같은 `sessionId`를 달고 있으므로(표본 서브 여섯 파일 356줄 전부 확인) 메인과 서브가 **같은 `s` 하나에 값을 쌓는다.** 그런데 어느 값을 쌓을지는 자리마다 다르다.

| 값 | 서브 호출이 들어가나 | 근거 |
|---|---|---|
| `s.cost` · `s.out` · `s.tok` · `s.cacheRead` | **들어감** | `server.js:311-314`에 `isSub` 조건 없음 |
| `s.activeMs` | **안 들어감** | `trackActive`가 첫 줄에서 서브를 되돌림 (`server.js:205`) |
| `s.breakCost` · `s.byCause` | 들어감 | `server.js:342-345` |
| `s.breaks` | 들어감(`sub:true` 표시) | `server.js:346` |
| `s.series` (그래프) | 안 들어감 | `if (!f.isSub)` 블록 안 (`server.js:353-373`) |
| `s.ttlMin` | 들어감 | `server.js:319`, §1.5에서 다룸 |
| `s.lastTool` · `s.asks` | 들어감 | `server.js:298` |

시간당 비용은 `cost / activeMs`다(`index.html:220`). 분자에는 서브가 들어가고 분모에는 안 들어가니, 표본에서 `$53.62 / 24.1분 = $133/h`가 나온다. 메인만 세면 `$13.22 / 24분 = $33/h`다. 네 배다.

**나중 구조.** 세션 `s` 아래에 서브 슬롯 맵 `s.subs`를 둔다. 키는 에이전트 id(파일명 `agent-<id>.jsonl`의 `<id>`), 값은 세션과 같은 모양의 작은 집계 객체다 — 비용 · 활성 시간 · 컨텍스트 · 호출 수 · 토큰 · 캐시 깨짐 목록과 원인별 집계 · 그래프용 시리즈. 레코드 하나를 처리할 때 맨 먼저 **"이 줄의 값은 누구에게 쌓나"**를 정한다.

```
지금:   f (파일)  ──모든 값──▶  s (세션 하나)          ← 서브도 여기 섞임. 단, 활성시간·그래프만 빠짐

나중:   f (메인)  ──────────▶  s (세션 = 메인 몫)
        f (서브 A) ─────────▶  s.subs.get('A')         ← 비용·활성·컨텍스트·깨짐·시리즈 전부 여기
        f (서브 B) ─────────▶  s.subs.get('B')
```

핸들러 안에서 이 대상을 변수 `g`로 받아 두면, 지금 `s.cost += cost`라 적힌 자리는 `g.cost += cost`가 된다. 값의 종류는 그대로고 **받는 그릇만 갈린다.** 그래서 메인의 값은 하나도 바뀌지 않는다 — 기존 픽스처는 전부 메인 파일만 있어서 `g === s`이고, 39건 테스트가 그대로 통과해야 한다.

**활성 시간.** `trackActive`(`server.js:204`)는 "모델이 실제로 돌던 구간"을 파일마다 `f.grp`로 묶어 두었다가 `flushGroup`에서 `s.activeMs`에 더한다. 그룹 자체는 이미 파일 단위라, 서브를 첫 줄에서 되돌리는 대신 끝까지 흘려보내고 `flushGroup`이 `g.activeMs`에 더하게 하면 된다. 다만 한 가지 — 이 함수는 `isSidechain: true`인 줄도 되돌리는데(`D-7`, v1.1.0), 서브 파일은 **모든 줄이** `isSidechain: true`다. 이 조건은 메인 파일 안에 옛 방식으로 섞여 들어온 사이드체인을 빼려는 것이므로 메인 파일에서만 본다.

**그래프 x축의 단조성(scope §4).** 시리즈의 x값은 `activeAt(s, f, ts)`가 낸다(`server.js:189`). 그 함수는 `s.lastA`로 "이번 x는 직전 x보다 작지 않다"를 보장한다. 대상을 `g`로 넘기면 서브 슬롯이 자기 `lastA`를 갖고 같은 함수를 타므로 **같은 성질이 그대로 성립한다.** 새로 만들 것이 없다.

**이름.** 서브 파일 옆에 `agent-<id>.meta.json`이 있고 `description`(사람이 읽는 한 줄) · `agentType` · `spawnDepth`를 담는다. `data/` 안 61쌍을 조사한 결과 — 짝 없는 `.jsonl`은 0건, `description` 없는 `.meta.json`은 1건(`{"agentType":"general-purpose"}`만 있음), `spawnDepth: 2`(서브가 띄운 서브)가 16건이며 이들은 **같은 `subagents/` 폴더에 평평하게** 놓여 있다. 이름은 `description` → `agentType` → 에이전트 id 순으로 있는 것을 쓴다. 깊이 2 서브는 scope §3대로 계층을 만들지 않고 평평한 목록에 그대로 올리되 깊이를 값으로 실어 보낸다.

### 1.2 세션 목록에 서브에이전트 행을 붙이고 고를 수 있게 한다

**지금.** 세션 목록 한 줄은 `renderList`(`index.html:187`)가 그리고, 오른쪽 화면은 전역 `selected`(세션 id 문자열 하나)를 보고 `renderMain`이 그린다. 시간 칸은 마지막 활동으로부터 지난 시간(`ago(now - s.lastTs)`)이다.

**나중.** 선택 상태를 `sel = { id, agent }`로 넓힌다. `agent`가 `null`이면 메인, 에이전트 id면 그 서브다. 목록은 세션 줄 아래에 서브가 있을 때만 들여쓴 줄 하나를 붙인다.

```
● 이슈 정리                          ← 세션 줄: 모델 · ctx · $13.22 · 활성 24m
    ● 서브에이전트 6                  ← 서브 줄: $40.40 · 활성 1.5h   (서브가 없으면 이 줄 없음)
● 다른 세션                          ← 
```

세션 줄을 누르면 `agent = null`, 서브 줄을 누르면 목록 첫 서브가 골라진다(D-4). 시간 칸은 `hrs(s.activeMs)`로 바꾼다(#26). 세션 줄의 비용 칸은 §1.1에 따라 자연히 메인 몫만 보인다.

### 1.3 서브를 고르면 TTL 카드 자리에 서브 목록이 나온다

**지금.** 상단 네 칸은 TTL 링 · Context · Cost · 캐릭터다(`index.html:248-289`). 아래는 그래프 · 캐시 깨짐 표 · State 칩이다. 전부 `s` 하나를 본다.

**나중.** `renderMain`이 세션 `s`와 **대상 `g`** 둘을 잡는다. 메인을 보는 동안 `g === s`라 지금과 같다. 서브를 보는 동안:

| 자리 | 메인을 볼 때 | 서브를 볼 때 |
|---|---|---|
| 첫 칸 | TTL 링 | **서브 목록** — 이름 · ctx · 비용 · 활성, 고른 것 강조, 누르면 `sel.agent` 교체 |
| Context | `s.ctx` · 구성 8층 바 | `g.ctx` · 단색 바(구성 없음, D-5) |
| Cost | 이 세션 · 오늘 누적 | **이 서브** · **서브 소계** |
| Cost 연비 | 이 세션 · 오늘 · 이 기기 | 이 서브 · 서브 소계 · 오늘 · 이 기기 |
| 캐시 깨짐 손실 | `s.breakCost` | `g.breakCost` |
| 캐릭터 | 세션 | 세션 (바뀌지 않음) |
| 그래프 · 깨짐 표 | `/api/detail?id=` | `/api/detail?id=&agent=` — 같은 그리기 코드 |
| State 칩 | 지금 그대로 | 모델 · effort · 도구 · stop · 호출 수 · 에이전트 종류 · 깊이 · 구간 |
| 왼쪽 아래 습관 표 | "이 세션" 열 = `s.byCause` | "이 서브" 열 = `g.byCause` |

그래프 코드는 지금 `b.sub`인 깨짐을 건너뛴다(`index.html:466, 477`). 이제 넘어오는 목록이 대상 하나의 것이므로 이 조건을 없앤다.

**캐릭터.** `charState`(`server.js:403`)의 `busy`가 `s.subActive`를 보지 않아, 서브만 돌 때 목록 불은 켜지는데 캐릭터는 `idle`이다. `busy`에 "서브가 3분 안에 움직였다"를 OR로 붙인다(scope §3의 딸린 표시).

### 1.4 서브에이전트 완료 알림을 사람이 친 프롬프트에서 뺀다

**지금.** `human` 판정(`server.js:280`)은 "메타가 아니고 · 서브 파일이 아니고 · 본문이 문자열이거나 text/image 블록만"이다. 표본 15건을 한 줄씩 열어 본 결과:

| # | 본문 첫머리 | 길이 | 실제 |
|---|---|---|---|
| 1 | `야 우리 이슈 정리좀…` | 129 | 사람 |
| 2~7 | `<task-notification>\n<task-id>…` | 6.6k~8.5k | 서브 1차 보고 |
| 8 | `.placeholder` | 12 | 사람(검토 구간 마커) |
| 9 | `적었어` | 3 | 사람 |
| 10~14 | `<task-notification>\n<task-id>…` | 2.1k~2.3k | 서브 2차 보고 |
| 15 | `<ide_opened_file>…</ide_opened_file>` **+ `없으니까 a하자`** | 273 + 8 | IDE 이벤트 **와 사람** |

**나중.** 걸러낼 태그 이름을 한 상수 `NOISE_TAGS`에 모으고, **블록 하나하나**를 "첫머리가 `<태그`로 시작하나"로 본다. 잡음 블록을 뺀 나머지가 하나 이상 있고 전부 text/image면 사람이다. 15번 레코드는 잡음 블록을 빼면 `없으니까 a하자` 하나가 남아 사람이다. 결과 **4**.

컨텍스트 구성(`f.comp`)에서는 잡음 블록의 글자 수를 "내 프롬프트" 층 대신 "시스템 리마인더/훅" 층에 더한다. 그 글자들은 컨텍스트에 실제로 들어 있으므로 없앨 수는 없고, 사람이 친 것이 아니라는 뜻으로 옆 층에 둔다. 표본에서는 알림 11건 약 7만 자가 옮겨 간다.

`NOISE_TAGS`에는 scope가 지목한 `task-notification` · `ide_opened_file`에 더해 `data/`에서 같은 모양으로 2건 관측된 `ide_selection`을 넣는다. IDE 이벤트라는 같은 부류이고, 목록 상수에 이름 하나 더 얹는 것이라 따로 항목을 세우지 않는다.

### 1.5 캐시 만료 판정을 세션 단위에서 호출 단위로 옮긴다 (#5)

**지금.** 원인 사슬(`server.js:329-336`)의 만료 조건은 `gapMin > (s.ttlMin === 60 ? 60 : 5)`다. `s.ttlMin`은 세션 하나의 값이고 서브 호출도 갱신하며(`:319`), 무엇보다 **판정 시점까지 읽힌 값**이다. 표본을 `replay`로 두 순서 모두 돌려 재확인했다:

| 읽는 순서 | `s.ttlMin` 최종 | 서브 깨짐 6건의 원인 |
|---|---|---|
| 메인 → 서브 (실사용) | 60 | `unexplained` |
| 서브 → 메인 | 60 | `ttl_expiry` |

같은 데이터인데 원인이 갈린다. 메인이 1시간 캐시(`cw1h > 0`)라 `s.ttlMin = 60`이 먼저 박히고, 서브는 5분 캐시(`cw1h = 0`, `cw5m` 12만~19만)인데 gap 25.8~28.4분을 60분 기준으로 재니 만료가 아니라고 나온다.

**나중.** 프레임이 직전 호출을 `f.prev`에 남기는데(`server.js:352`), 거기에 **그 호출이 어느 TTL로 썼는지** `ttlMin`을 하나 더 싣는다. `cw1h > 0`이면 60, `cw5m > 0`이면 5, 둘 다 0(캐시에 쓴 게 없는 호출)이면 직전 값을 잇는다(D-6). 만료 조건은 `prev.ttlMin`을 본다. `f.prev`가 파일 단위이므로 메인은 메인의 TTL로, 서브는 서브의 TTL로 각자 판정된다. `s.ttlMin`은 TTL 카드 · 잔여 시간 · 캐릭터가 계속 쓰므로 남기되 메인 호출로만 갱신한다.

`data/` 전체 51,996건의 호출에서 `cw > 0`인데 1h/5m 세부가 없는 호출은 **0건**이다. 그러니 D-6의 이음 규칙은 거의 타지 않고, 기존 픽스처(세부 없이 `cache_creation_input_tokens`만 있음)에서만 "직전 값 → 세션 값 5"로 떨어져 지금 동작과 같아진다.

## 2. 결정

### D-1 서브를 어디에 두나

- 선택지
  - a. 세션 안에 슬롯 맵 `s.subs`를 두고 핸들러가 대상 `g`를 골라 쌓는다 — 대가: 핸들러의 `s.` 대입 스무 곳 남짓을 `g.`로 바꾸고 어느 것이 세션 몫(프롬프트 · 압축 조언 · 캐릭터 · 커밋 수)인지 하나씩 가른다.
  - b. 서브를 `sessions` 맵에 별도 세션으로 등록한다(id = 에이전트 id, 부모 id 보관) — 대가: 시리즈 · 깨짐 · 활성이 공짜로 생기지만, 세션 목록 · 보정(`calibrate`) · 폴더 합계 · 탭 제목이 전부 서브를 세션으로 오인하므로 매번 걸러야 한다. 부모-자식 연결도 따로 든다.
- 고른 것: a. 이유: 서브는 세션의 부분이지 세션이 아니다. 걸러야 할 자리가 쌓아야 할 자리보다 많다.

### D-2 폴더 합계("오늘" · "이 기기")에 서브를 넣나

- 선택지
  - a. 비용과 활성 시간 둘 다 넣는다 — 대가: 여섯이 동시에 돌면 활성 시간이 벽시계보다 길어져 "오늘" 시간당 비용이 낮게 보인다(표본: `$53.62 / (24m + 90m)`).
  - b. 둘 다 뺀다(메인만) — 대가: "오늘 누적"에서 서브가 태운 `$40.40`이 사라진다. 돈이 빠져 보인다.
  - c. 지금처럼 비용만 넣는다 — 대가: 세션에서 고친 분자·분모 불일치가 폴더 줄에 그대로 남는다.
- 고른 것: a. 이유: 연비 위젯의 정의가 "모델이 실제로 돌던 시간"이고(`index.html:219` 툴팁), 태운 돈은 전부 보여야 한다. 분자와 분모가 같은 대상을 가리켜야 한다는 이 사이클의 원칙과도 맞는다.

### D-3 잡음 판정의 단위

- 선택지
  - a. 블록 단위 — 잡음 블록을 빼고 남은 것으로 판정 — 대가: 없음에 가깝다. 코드 두 줄.
  - b. 레코드 단위 — 잡음 블록이 하나라도 있으면 사람이 아님 — 대가: `data/`의 IDE 이벤트 9건이 전부 사람 글을 뒤에 달고 있어 9건이 빠진다.
- 고른 것: a. 이유: 위 표. 그래서 표본은 3이 아니라 4다.

### D-4 서브 줄을 누르면 무엇이 골라지나

- 선택지
  - a. 목록 첫 서브(시작 시각 순)가 바로 골라진다 — 대가: "서브 전체"만 보는 화면이 없다. 소계는 Cost 카드와 목록 줄에서 본다.
  - b. "소계 화면"을 하나 더 둔다 — 대가: Context 카드에 소계로 보일 값이 없다(컨텍스트는 더할 수 없다). 그래프도 그릴 대상이 없어 빈 칸이 생긴다.
- 고른 것: a. 이유: 대상은 언제나 하나여야 화면 전체가 한 값을 가리킨다(scope §2.3의 원칙).

### D-5 서브의 컨텍스트 구성(8층)

- 선택지
  - a. 만들지 않는다 — 단색 바, 범례 없음. 그래프도 단색 채우기 — 대가: 서브가 무엇으로 컨텍스트를 채웠는지는 안 보인다.
  - b. `!f.isSub` 가드를 걷어 서브도 `f.comp`를 쌓는다 — 대가: 가드가 일곱 군데고, 압축 조언(`compactAdvice`)은 서브에 뜻이 없어 따로 막아야 한다.
- 고른 것: a. 이유: scope §2.3이 요구하는 것은 컨텍스트 · 비용 · 활성 · 그래프다. 화면은 `comp`가 없을 때를 이미 다룬다(`index.html:327, 448`).

나머지는 갈림길이 아니다.

- D-6 직전 호출이 캐시에 아무것도 안 썼을 때의 TTL: 그 전 호출의 `ttlMin`을 잇고, 첫 호출이면 `s.ttlMin`. §1.5.
- D-7 `.meta.json`은 `scan`이 아니라 `readFile`에서 서브 프레임을 만들 때 읽는다. `replay(파일)`처럼 `scan`을 거치지 않는 길도 덮고, 처음에 없으면 다음 읽기에서 다시 시도할 수 있다.
- 이름 순서: `description` → `agentType` → 에이전트 id. §1.1.
- 깊이 2 서브는 평평한 목록에 그대로, `depth` 값만 실어 State 칩에 보인다. §1.1.
- `s.byCause[cause].sub` 소집계는 지운다. 서브 깨짐이 서브 슬롯으로 가므로 뜻이 없고, 화면 · 테스트 어디도 읽지 않는다.
- `s.commits` · `lateCalls` · `nightCalls` · `streak`는 손대지 않는다. 화면이 읽지 않는 필드다.
- 캐릭터는 서브의 캐시 깨짐에 반응하지 않는다(`lastAvoidableBreakTs`는 메인만). scope §3.

## 3. 성공 기준

| SC | 기준 | 검증 수단 | 판정 시점 |
|---|---|---|---|
| SC-1 | 서브 파일을 함께 읽어도 메인의 `cost` · `activeMs`는 메인만 읽었을 때와 같고, 서브 슬롯의 비용 · 활성이 각각 서브 파일에서만 나온다. 표본에서 `cost + subTotal.cost`가 `$53.62`다 | `node --test` (합성 픽스처) · `curl /api/state` (표본) | do B-2 |
